# 진행 상황과 결정 (인수인계)

마지막 갱신: 2026-11-11. 사이트: https://limbus-trpg.vercel.app · 저장소: github.com/Semimail/limbus-trpg

## 구현 완료
- 로그인(디스코드), 사무소 허브(세션·의뢰 게시판·내 캐릭터·파티원·기록 보관소·적 도감·GM 패널·캠페인 삭제·룰 설정 링크), 초대 코드, 임시 GM.
- 캐릭터: 6단계 위자드(기본[대사·정체성·면모3·배경] → 능력치 → 특기 → 스킬[틀 선택+이름·속성·효과·이미지, 직접 조정] → E.G.O → 확인), 포스터형 시트 보기(검정·빨강·금색), GM 조정(레벨·체력·정신력·빛·침식도·동기화·승인), 편집, 삭제.
- 적 도감: 등록/편집(스킬·기믹·저항·속도·정신력), 플레이어는 마주친 적과 사용된 스킬만(???), 기믹 개별/전부 공개.
- 세션: 장면(드라마/탐색/전투) 추가·전환, 채팅 5종+이미지+실시간, 명령(/r, /coin N|능력치 [난이도] [+보너스] [빛], /vs), GM 메시지 삭제, 장면 보드(배경·토큰 드래그), 세션 종료, 내보내기(JSON), 세션 삭제.
- 전투 보드: GM 준비 → 속도 → 손패 3장 선택(방어·E.G.O 항상) → 가로채기 → 라운드 자동 처리(합·일방·흐트러짐·상태이상·치명타·효과) → 채팅 로그·적 스킬 자동 공개 → 종료 시 시트 반영. GM 수동 조정, 빛 손패 교체, E.G.O 발현·침식.
- 리플레이(/replay, 로그인 불필요), 데이터북(/databook, 43항목)과 키워드 팝업(어디서나 단어 클릭), 룰북(/rulebook ← docs/rulebook.md).
- 캠페인 룰 설정(/campaigns/[id]/settings): 저항·흐트러짐 구간·배율·정신력 변동·침식·성장 공식.
- 성능: Vercel icn1, getClaims, pg_cron keep-warm, Supabase Pro+Micro.

## 확정된 룰 (요약, 자세한 건 docs/rulebook.md)
- 코인: 앞면 50%+정신력%. 정신력 -45~45, 세션 내 유지, 합 승+10/패-10.
- 능력치 죄악 7종(1~5, 총 14, 5는 하나). **죄악 7종 유지 확정(피라미드 안 함).**
- 특기 2개(문장 → 자동 효과 파서), 공격 3+방어 1, 스킬 틀 프리셋, 기대 위력 상한(1레벨 5/7/10/방어 7, 레벨 배율).
- 등급 7×7=49레벨(설정값). 체력 100×1.15^(L-1), 위력 1.08^(L-1), 코인 상한 2+L/4(최대 14).
- 흐트러짐 50/30%(1회씩), 행동 불가·피해 2배. 치명타 = 호흡×5%, 1.5배 고정.
- 상태이상 7종 숫자 하나·발동 후 절반(출혈은 공격 코인마다, 합 코인 제외; 진동은 흐트러짐 배율 가산).
- E.G.O: 정신력 지불·침식도·횟수, 정신력<0이면 코인 뒷면 시 침식, 침식도 100 강제. 침식 라운드는 자동 조종.
- 빛 3: 손패 교체 / 판정 코인 +1.
- 저항·공명은 구현만, 기본 꺼짐. 동기화 3단계 속도 다이스 2개.

## 사용자에게 물어둔 것 (답 대기)
1. 키워드 구매(코스트) 방식 vs 현재 기대 위력 상한 방식(절충: 효과 1줄당 상한 -1).
2. 빛/경험치 이름을 운명점/성장점으로 바꿀지.
3. 면모를 규칙화(면모 걸고 빛 써서 +2)할지, 서사 태그로 둘지.
4. 등급 문양 아이콘(드라이브)을 시트에 넣을지.
5. 시트 배치에서 더 바꿀 것.
- 룰북 부록 B 미결: 배경 효과, 동기화 최소 레벨, 패시브 해금, 침식도 자연 감소, 회피 고유 효과, 경험치 기준.

## 보안 메모
- 초기 설정 중 사용자가 Supabase 관리 토큰(sbp_…), 디스코드 Client Secret, DB 비밀번호를 채팅에 붙여 넣었음. **재발급/삭제를 권고했고, 아직 사용자 확인 없음.** 새 세션은 그 값을 쓰지 말고 필요 시 request_credential로 새로 받는다.
- 플레이어는 전투 상태(combats)와 장면(scenes) UPDATE 권한이 있음(서버 액션에서 검증). 초대받은 사람만 전제.

## 격자 전술 레이어 (2026-11 추가, 사용자 승인 "응 그렇게 하자")
- 엔진 `packages/rules/src/grid.ts` + `combat.ts`: 10×6 격자(설정 `gridEnabled/gridCols/gridRows/moveBonus/protectLightCost/protectRange`), 배치(아군 0~1열, 적 끝 두 열), 이동력 = 최고 속도 슬롯 + moveBonus, `moveUnit`(한 칸씩, 아군 통과·적 차단, 기회 공격 = 인접 적이 공격 스킬 1코인 일방 공격, `preRound` 이벤트), `setPick` 사거리 검사(`skill.range`, 기본 1 = 주변 8칸), 보호(`pick.protect`: 빛 소모, 자리 교환, 확정), 가로채기 격자 조건(공격자 인접 또는 공격 직선 위), 재지정도 사거리 안에서만. 적 AI는 라운드 시작에 가장 가까운 대상 쪽으로 이동 후 사거리 안이면 선택. 테스트 `test/grid.test.ts` 포함 65개 통과. 기존 테스트는 `NOGRID`.
- 웹: `battle-screen.tsx`(구 `board.tsx` 대체) — 참고 영상(FVTT+림버스 모듈) 레이아웃의 전체 화면 전투 UI: 어두운 캔버스 가운데 격자 지도(토큰=초상화, 체력 바, 이동 가능 칸·사거리 음영, 의도 화살표, 셀 크기 자동), 상단 바(장면·라운드·GM 버튼·장면 전환), 우측 상단 유닛 패널/명단/로그 탭, 하단 스킬 독(슬롯 탭 + 림버스식 스킬 칩, 대상 거리, 보호·가로채기), 맨 아래 붉은 속도 트래커, 오른쪽 채팅 열. 모바일은 세로 스크롤. `moveUnitAction`(소유자/GM, 낙관적 동시성), PickRow 보호 체크박스(노려지는 주변 아군 선택), 룰 설정 "격자" 패널, 스킬 에디터/위자드/카드 사거리, 로그·연출 `move`/`opportunity`.
- 룰북 5장 "격자 (위치)" 절, 3장 스킬 사거리 문구 추가.
- 미결: 이동 애니메이션 없음(즉시 반영), 지형/장애물 없음(필요하면 `passable`에 블록 셀 추가), 모바일에서 격자는 가로 스크롤.
